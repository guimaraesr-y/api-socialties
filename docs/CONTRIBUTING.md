# Contribuindo para o 🌍 Socialties - RESTful API

Obrigado por seu interesse em contribuir para o **Socialties**! 🎉  
Sua ajuda é fundamental para melhorar e expandir este projeto. Este guia descreve as diretrizes e o processo para contribuir.

---

## 🚀 Como Contribuir

1. **Fork o Repositório**  
   Clique no botão de **Fork** no topo da página para criar sua cópia do repositório.

2. **Clone o Repositório**  
   Clone seu fork para o ambiente local:
   ```bash
   git clone https://github.com/<seu-usuario>/api-socialties.git
   cd api-socialties
   ```

3. **Crie um Branch para Sua Contribuição**  
   Use um branch separado para fazer suas alterações. Nomeie-o com algo descritivo:
   ```bash
   git checkout -b feature/adicionar-imagem-perfil
   ```

4. **Faça Suas Alterações**  
   Adicione suas mudanças ou melhorias no código e commit suas alterações:
   ```bash
   git add .
   git commit -m "Adiciona funcionalidade de upload de imagem de perfil"
   ```

5. **Sincronize com o Repositório Original**  
   Antes de enviar seu PR, sincronize seu fork com o repositório original para evitar conflitos:
   ```bash
   git pull upstream dev
   ```

6. **Envie para Seu Fork**  
   Suba o branch com suas alterações para o seu fork:
   ```bash
   git push origin feature/adicionar-imagem-perfil
   ```

7. **Abra um Pull Request (PR)**  
   - Vá até a página do seu fork no GitHub.
   - Clique no botão **Compare & Pull Request**.
   - Adicione um título e descrição claros para o PR.
   - Envie o PR para revisão.

Obs: Sua branch deve ser criada a partir da branch `dev`. 🌿

## 🛠️ Padrões de Código

Siga estas boas práticas para manter o código consistente e fácil de manter:

- Use **Java 17** como versão padrão.
- Respeite o estilo de código definido pelo **Spring Boot** e **Java**.
- Comente o código onde necessário, explicando a lógica.
- Adicione testes unitários para novas funcionalidades.

---

## 📋 Diretrizes para Contribuição

- **Antes de começar**, confira as [Issues](https://github.com/guimaraesr-y/api-socialties/issues) abertas e veja se algo já está em andamento. Se não, sinta-se à vontade para abrir uma nova Issue descrevendo o problema ou a funcionalidade desejada.
- Se possível, associe o seu PR a uma Issue existente, adicionando `Fixes #<número_da_issue>` ou `Closes #<número_da_issue>` ou `Resolves #<número_da_issue>` na descrição do PR.

---

## 🧪 Testes

Para garantir a qualidade do código, execute os testes antes de enviar um PR:

1. Execute os testes com o Maven:
   ```bash
   ./mvnw test
   ```

2. Adicione testes para novos recursos ou corrigir falhas encontradas.
